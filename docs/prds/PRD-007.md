## Проблема
В код-ревью PR #131 (выполнен 2026-05-03) были найдены 4 medium-issue, которые приняли решение отложить как follow-up. Плюс пара мелких проблем UX, всплывших в эксплуатации. Пора закрыть.

| # | Issue | Откуда |
|---|---|---|
| 1 | `selectedRepo` в `ProjectsView` не сохраняется в URL — refresh браузера на странице Health возвращает к списку проектов | code review |
| 2 | Дубликат правил в YAML: `knowledge.business_logic_present` и `ops.new_project_missing_business_logic` шлют один сигнал | code review |
| 3 | `pathExists` использует case-sensitive matching по `name`. Репо с `README.MD` (заглавный) даст false-fail | code review |
| 4 | `coverage_threshold` дёргает shields.io без retry — единичный network glitch даёт `unknown` | code review |
| 5 | Концурентный пробег правил — `for (i+=5) Promise.all(batch)` ждёт самый медленный батч. Не critical сейчас, но если drift-скан Эпика C добавится — нужно semaphore | code review |

## Решение
Каждый пункт — отдельная маленькая задача:

1. **URL persistence**: при `setSelectedRepo(x)` обновляем URL через `history.pushState({ repo: x }, '', '?repo='+x)`. На mount читаем `URLSearchParams`. Слушаем `popstate` — браузерная «назад» возвращает к списку.
2. **Дубликат правил**: PR в `makeit-knowledge` — оставить `knowledge.business_logic_present` (бесусловное наличие), убрать `ops.new_project_missing_business_logic` (был fallback для случая «новый проект»). Логика «grace для новых проектов» уже в общем `grace_period_days`.
3. **README casing**: добавить флаг `case_insensitive: true` в `pathExists`, дефолт false. Использовать в правилах гигиены через явное `case_insensitive: true` на уровне check spec.
4. **shields.io retry**: 1 retry с exponential backoff (250ms, 1s) внутри `coverage_threshold`. После 2 неудач — `unknown`.
5. **Semaphore**: новый утиль `src/utils/semaphore.ts` — простой `class Semaphore { acquire(); release(); }`. Заменить batched-loop в `runHealthCheck`. Тривиально, не больше 30 строк.
