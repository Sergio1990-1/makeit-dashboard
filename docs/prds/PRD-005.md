# PRD-005: Action wiring — создание GitHub Issues из health-findings

## Метаданные
- Статус: draft
- Автор: Sergei
- Дата: 2026-05-03
- Приоритет: P2-high
- Scope: small (3 задачи)
- Связан с: PR #131 (Project Health page); PRD-004 (Insights — карточки тоже получат эту кнопку)

## Проблема
Health-страница ловит реальные fails (CONTRIBUTING.md отсутствует, CI красный, milestone Epic-001 просрочен, 13 PR без правок docs/), но единственный способ их пофиксить сейчас — открыть GitHub в новой вкладке и руками создавать issue. Это:

- Тормозит куратора — каждый findings = 5+ кликов и копи-паст
- Теряет контекст — `detail` и `remediation` из движка не попадают в issue
- Создаёт дубликаты — нет защиты от того что issue с тем же title уже открыт
- Игнорирует трекер — issue создаётся без `gh project item-add 1`, нарушает GLOBAL_CLAUDE.md

В дизайне `ProjectHealthPage.tsx` кнопка предусмотрена, но не подключена.

## Решение
Подключаем существующий `createIssue` + `addIssueToProject` из `github-actions.ts` к UI:

1. **Single-click create** — на каждой fail-карточке `FindingsBoard` появляется кнопка «→ issue». Клик: дедуп по title → если нет дубля → `createIssue` → `addIssueToProject(1)` → toast `«Создан #NNN»` со ссылкой.
2. **Bulk modal** — кнопка «Создать issues по всем findings» в `Hero` или `Topbar` страницы. Открывает модалку: список fail-findings с чекбоксами (по умолчанию все выбраны, кроме severity=low), preview body для каждого, общий submit «Создать N issues». Прогресс-бар во время создания (последовательно, чтобы не словить secondary rate limit). Итог — toast с числом созданных и ссылками.
3. **Защита от дублей** — перед `createIssue` дёргать `gh issues --search "is:open in:title <title>"` через REST. Если найден открытый issue с точно тем же title — пропустить с пометкой «уже есть, #NNN».

Title issue: `[health] {rule.title}` — например `[health] CONTRIBUTING.md в корне`.
Body issue:

```
## Health-finding

**Правило:** `{rule_id}` (severity: {severity})
**Слой:** L{layer} — {layer_title}

## Что не так

{detail}

## Что делать

{remediation}

## Источник правила

{source} → [PROJECT_CHECKLIST.yaml](https://github.com/Sergio1990-1/makeit-knowledge/blob/main/Skills/PROJECT_CHECKLIST.yaml)

## Контекст

- Repo: {repo}
- Tier: {tier} {complex} {client}
- Сгенерировано из health-скана {generated_at}
```

Лейблы: `tech-debt` + severity-маппинг:
- `critical` → `P1-critical`
- `high` → `P2-high`
- `medium` → `P3-medium`
- `low` → не добавляется priority-лейбл

## Пользователи и роли
| Роль | Что делает | Ключевые потребности |
|------|-----------|---------------------|

## Функциональные требования
| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-1 | На каждой fail-карточке кнопка «→ issue». Disabled если отчёт в loading или token отсутствует | must |
| FR-2 | Title формируется как `[health] {rule.title}`; body — по шаблону выше; лейблы: `tech-debt` + severity-маппинг | must |
| FR-3 | Перед созданием — search существующих open issues с тем же title через `gh api repos/{owner}/{repo}/issues?state=open` + filter в JS. Если найден — toast «уже есть, #NNN», ссылка | must |
| FR-4 | После создания — сразу `addIssueToProject(token, owner, repo, issueNumber, 1)` (трекер MakeIT) | must |
| FR-5 | Toast feedback: success → `«Создан #NNN [link]»`, duplicate → `«Уже есть #NNN [link]»`, error → текст ошибки | must |
| FR-6 | Bulk modal: открывается из шапки Health-страницы кнопкой «Создать issues по всем» (показывается только если есть fails). Модалка: список с чекбоксами (default: severity ≥ medium), preview body для каждого, кнопка submit | must |
| FR-7 | Bulk-create: последовательное создание (await per-issue), прогресс-бар, после завершения — sticky toast с числом созданных + ссылка на trekker фильтр `is:issue is:open label:tech-debt label:health-{repo}` | must |
| FR-8 | Если bulk-create частично упал (например, 3 из 7 успешно) — показать оба числа и список ошибок | should |
| FR-9 | На карточке инсайта на главной (после реализации PRD-004) — та же кнопка «→ issue» | should |

## Нефункциональные требования
- **Латентность**: single create ≤ 3 секунды (search + create + add-to-project = 3 REST вызова).
- **Bulk size**: не пытаться создавать > 30 issues за раз — модалка ограничивает выбор + warning при превышении.
- **Идемпотентность**: повторный клик «→ issue» при существующем дубле не создаёт второй; повторный клик после успешного создания — кнопка disabled, показывает «#NNN ✓».

Регрессии:
- При большом числе fail (mankassa-app: 10 fails) bulk-modal может казаться перегруженной — mitigation: severity-фильтры в шапке модалки.
- GitHub secondary rate limit (~80 запросов в минуту на запись) — mitigation: 1 секунда между запросами в bulk-режиме.

## Критерии приёмки
- [ ] Клик «→ issue» на fail-карточке: за ≤ 3 сек появляется toast с номером созданного issue
- [ ] Созданный issue имеет правильный title, body со всеми секциями, лейблы `tech-debt` + соответствующий priority
- [ ] Issue добавлен в MakeIT Tracker (gh project 1) — проверяется через `gh project item-list 1 --owner Sergio1990-1`
- [ ] Повторный клик «→ issue» по тому же finding: тост «уже есть #NNN»
- [ ] Bulk-modal: создаёт N issues последовательно, показывает прогресс, итог с ссылками

## Открытые вопросы
- [ ] **Дедуп по точному title или fuzzy?** Точный — простой, но создаст дубли при изменении формулировки правила в YAML. Fuzzy — тяжёлый.  **Решение**: точный (rule_id вшит в title через `[health]`-префикс — стабилен при изменении формулировки `rule.title`). После недели реальной эксплуатации — пересмотреть.
- [ ] **Куда добавлять issue в трекер — в первый `Sergio1990-1/Project 1`?** **Решение**: да, GLOBAL_CLAUDE.md диктует именно его.
- [ ] **Если у пользователя нет write permission на repo (например, чужой open-source)?** **Решение**: 12 наших проектов все на `Sergio1990-1` под одним токеном — write всегда есть. Edge-case оставляем на будущее.
