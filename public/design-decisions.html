10 Motion durations

CLAUDE ≡ CODEX → 120/200/300ms

Длительности transitions. Сейчас в tokens.css: fast=120ms, base=200ms, slow=300ms.

Сейчас

0.1s..0.3s вперемешку

В коде: 0.1s, 0.15s, 0.2s, 0.3s — каждый компонент выбирает свою длительность интуитивно.

Несогласованность на hover-эффектах. Hover карточки 0.2s, hover кнопки 0.15s, hover навигации 0.1s.

Claude

120 / 200 / 300 (fast / base / slow)

fast 120ms — hover-tint, color shifts
base 200ms — layout (translate, scale)
slow 300ms — modals, overlays

Стандартный диапазон Material/Apple. Easings: ease-out (вход), ease-in-out (трансформы), ease-spring (intra-card).

«120/200/300ms — согласен»

✓ match

Codex (review #2): «D10 120/200/300ms — согласен». Решение зафиксировано.

14 Loading variants — когда какой

CANON → 3 типа по контексту

Skeleton vs spinner vs branded loader — где какой применять.

Сейчас

BrandedLoader на refresh

Cold-start → BrandedLoader (full-screen matrix)
Refresh → опять BrandedLoader (повторно показывают)
Skeleton-ы используются в AI Insights

BrandedLoader включается даже на ручной refresh — это раздражает: только что видел данные, теперь снова матрица на 5 секунд. Skeleton редко.

Claude

Skeleton / Spinner / Branded — по контексту

Skeleton — для списков и карточек (известная форма)
Spinner (pulse-dots) — для refresh / inline actions
Branded — только cold-start (первый mount)

Branded красивый — но дорогой по вниманию. Использовать редко. Refresh уже виденного контента — spinner или вообще ничего (warm-update).

Codex

3 варианта в перечне

✓ match

Codex перечислил «Loading (skeleton, spinner)» — а branded подразумевается. Семантика разнесения одобрена.

15 Error pattern — inline vs модал

CANON → inline error

Когда API упал или загрузка не удалась — где показывать ошибку.

Сейчас

Кто как

ErrorBoundary — dashed red border
useDashboard — отдельный baner вверху
ChatPanel — модал?
Audit — inline red text без structure

Юзер не знает где искать ошибки. Когда что-то сломалось — неясно «это локальная проблема одного блока или вся вкладка не работает».

Claude

Inline error в зоне

Не удалось загрузить данные.

Ошибка показывается в той зоне, которая сломалась. Не модал (модал = всё работает, но один диалог). Не toast (toast = мимолётная нотификация).

В перечне State patterns

✓ match

Codex упомянул «API error» как требующий унификации. Inline-вариант с retry — стандартный паттерн для дашбордов.

16 Stale data threshold

CANON → 5 минут

Сколько должно пройти, прежде чем показывать предупреждение «данные устарели».

Сейчас

Только timestamp

Везде показано «обновлено N мин назад» — но без визуального предупреждения. Юзер сам должен заметить «о, час назад» и обновить.

Stale без warning = юзер принимает решения по устаревшим данным.

Claude

5 минут → warning banner

⚠ Данные устарели — 38 мин назад

Под 5 минут — обычный «обновлено X назад». Над 5 — warning. Над 30 — error-tone. Конкретные пороги можно подкрутить под потребности.

Codex

В перечне

✓ match

«Stale data» в списке требуемых patterns. Конкретный threshold — детализация.

18 Repo color identity

CLAUDE ≡ CODEX → mood-only (+ glyph/dot для milestones)

Должен ли каждый репозиторий иметь свой узнаваемый цвет (как в GitHub-language-bar) или цвет всегда несёт семантику (статус, severity).

Сейчас

Mood-only

Все репо в heatmap, графиках — brand-blue.
Цвета — это статусы (success / danger), не identity.
Repo узнаётся по имени, не цвету.

Универсально, не размывает семантику. Минус — в большом наборе репо сложно отслеживать «вот этот столбик — это какой проект».

Claude

Mood-only — без identity

Для портфеля 12 репо identity-палитра скорее шумит. Цвет должен означать state, не kind.

Если нужно отличать репо — лучше через icon / repo-name chip.

Identity-палитра требует mapping repo→color в config.ts. Это +ещё одна сущность, которая должна обновляться при добавлении репо. Усложняет.

Codex

«Mood-only, glyph/dot для milestones»

✓ match

Codex (review #2): «mood-only согласен; постоянную repo-палитру не вводил бы, кроме маленьких glyph/dot в milestones» — оговорка зафиксирована как exception, основное решение принято.
